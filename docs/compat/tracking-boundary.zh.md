# 文件回退的追踪边界

> 回退文件时，插件**只写回它记录在文件检查点里的状态**：每条用户消息一张稠密清单。文件在被写类工具（`write`、`edit`）首次触碰时进入记录；此后每张保留的检查点都为它带一行。还原会与真实磁盘对账，绝不猜测。
>
> 因为每个消息边界的清单都是稠密的，目标消息通常对当时已跟踪的每个路径都有行。记录有两类缺口：文件进入追踪之前的历史（边界一），以及下面几处。这些都是**有意取舍**（与 Claude Code 的检查点语义一致）。

## 一、检查点是什么

检查点只回答一个问题：

> **那条消息开始时，每个已跟踪文件是什么？**

- **每条用户消息一张检查点**，中途插话（steering）也一样：DSH 在 step 边界 claim 插话，把它作为普通的 `user/message` 落库，它也是普通的回退目标。
- **稠密**：清单一刻也不省略，对当时的每个已跟踪路径都有一行 `path → 状态`，不是相对上一条消息的增量。
- **状态**要么是指向版本文件的引用（确切字节），要么是 `null`（那一刻文件不存在；还原 `null` 就是删除文件）。
- **内容共享**：内容未变的文件在多张检查点里复用同一个版本；只有字节不同才写新版本。
- **追踪列表**：路径第一次被写类工具触碰时加入，之后一直保留。插件不扫描工作区；从未加入列表的文件没有任何检查点行。

## 二、记录在什么时候建立

**在消息边界。** 在 step 把消息落库之前、在任何模型调用或工具执行之前，插件重读所有已跟踪路径，为这一批 claim 到的每条用户消息（含插话）写一张稠密清单。自上一张检查点以来变过的文件在这里得到新版本；没变的重用旧版本。外部编辑——Bash 命令、构建脚本、编辑器保存——就是这样进入记录的：下一个消息边界会看到它。

**在首次触碰。** 当 `write` / `edit` 指向一个尚未被追踪的路径时，插件在**工具主体执行之前**记下它的状态：文件还不存在时记 `null`，否则记当前字节。这一行作为版本 1 加入当前消息的检查点。被拒绝或在派发前被取消的调用走不到这里，什么也不记；调用被派发后即使工具失败或被取消，也只留下无害的「改动前」行。

**未变的编辑不记录。** 路径一旦进入追踪，编辑本身不产生新行；下一个消息边界记录改动后的内容。未变的文件不产生新版本。

## 三、还原：只以记录为唯一标准

1. 把目标 seq 解析为它的 `user/message` 事件，再取该消息的 `id`；检查点文件以这个 id 为键。
2. 目标消息**没有检查点**时，不对文件做任何操作。对话回退照常执行，结果里报告该目标「没有文件检查点」。
3. 否则遍历**最新**保留检查点的键集（即当前追踪集），这样目标之后才创建、后来被追踪的文件也会被纳入。
4. 每个路径优先取目标检查点自己的行；目标早于该路径时，取它**之后最早**的一行——即 v1 兜底，也就是首次触碰之前的状态。
5. 与真实磁盘比较：一致则不做操作；不一致则写回记录的版本（`null` 行则删除）。只触碰有行的路径，每次写入都是目标目录内的原子替换。

重复回退是幂等的：每次执行都从真实磁盘重新计算，已经到达目标状态的文件不会被触碰。中途崩溃的还原可以再跑一次收敛。

少数路径会被跳过并报告，不写入：末段不是单个普通文件（符号链接、硬链接、FIFO、设备）、父目录已不在捕获时的位置、当前文件超过体积上限的还原，以及没有任何记录行的路径。每个跳过的路径都会带原因列出，每个失败的文件单独列出。删除不受上限拦截。

比较内容先走 `(size, mtime)` 快路径，再读字节。若有工具在保持大小不变的同时把 mtime 改旧，可能漏判一次变化——这与 Claude Code 是同一个取舍。

## 四、边界一：文件进入追踪之前的历史

**被写类工具处理过，是文件加入追踪列表的前提。** 在此之前它经历的所有外部编辑都没有行，之后也不会有任何来源为它补记。两种情形：

**整个会话都没有处理过它。** 回退到任何消息，插件对该文件都只能报告没有可还原的改动。

**后来处理过它（更常见）。** 记录从首次触碰开始，因此更早的历史无法还原。下面的例子里 `v0` 是插件从未见过的历史：

| 消息 | 回合内发生 | 文件内容 | 行：这条消息开始时是什么 |
| :---: | --- | :---: | --- |
| 1 | — | `v0` | （无：文件还没有进入追踪） |
| 2 | 手动编辑 | `v0` → `v1` | （无：同上） |
| 3 | 手动编辑 | `v1` → `v2` | （无：同上） |
| 4 | `edit` 首次触碰 | `v2` → `v3` | `v2`（改动前的状态；文件从这一刻进入追踪列表） |
| 5 | — | `v3` | `v3`（边界看到改动后的内容） |

回退到消息 5 → `v3`；消息 4 → `v2`；而**回退到消息 1、2、3 也都会得到 `v2`**——它们之后最早的行就是消息 4 的改动前行。`v2` 确实是文件首次被触碰那一刻的内容，但这三条消息开始时的真实内容分别是 `v0`、`v0`、`v1`，插件从未见过，无法还原。

## 五、记录中剩余的缺口

每个消息边界的清单都是稠密的：目标消息对当时已跟踪的每个路径都有自己的一行。后来才被追踪的路径只有它的改动前行（边界一的首次触碰状态）。剩下的缺口是下面这些。

### 超过体积上限

已跟踪文件超过体积上限（默认 8 MiB，可用插件配置项 `maxFileBytes` 调整，`0` 关闭）时，不产生新版本。每个消息边界保留**上一条行**。当前文件超过上限时，还原会跳过并报告它。文件回到上限以下后，回退到超限期间的消息会还原**最后记录的状态**，这个状态可能早于超限的那一段——那一段的字节从未被记录，无法恢复。

| 消息 | 回合内发生 | 文件内容 | 行 |
| :---: | --- | :---: | --- |
| 1 | `write` 新建 | `—` → `A` | `null` |
| 2 | 增长超过上限 | `A` → `G1` | `A`（超限：保留上一条行） |
| 3 | 再次编辑 | `G1` → `G2` | `A`（超限） |
| 4 | 缩小 | `G2` → `B` | `A`（消息到达时超限） |
| 5 | `edit` | `B` → `X` | `B`（回到上限以下：边界记录它） |

回退到消息 5 → `B`。回退到消息 2、3、4 → `A`，即最后记录的状态；`G1`/`G2` 那一段不在记录里。回退时文件超过上限的，任何目标都会跳过它并报告上限。

**首次被看到时就超限**的文件不会加入追踪，因此没有行，也不出现在预览的超限列表里。

### 主动关闭检查点

`fileCheckpointingEnabled` 关闭期间（配置卡片沿用「快照备份」的界面标签），不写任何新检查点或首次触碰行。这个期间发出的消息没有检查点，回退到它们只做对话回退，并报告没有文件检查点。关闭期间首次被触碰的文件不会进入追踪；重新开启后，下一个消息边界重新开始记录已跟踪文件。某个 step 或工具看到开关关闭时，当前检查点引用会被丢弃；如果开关在观察之前重新打开，关闭期间是一段没有记录的缺口，首次触碰只能记下它关闭之后、触碰之前的状态。

### 插件在一轮进行中挂载，或接入没有检查点的会话

插件挂载之后，在下一次被接纳的 step 之前还没有当前检查点。这一轮余下的首次触碰会被跳过，因此那时新触碰的文件不会进入追踪。插件检查点存在之前的历史消息——旧会话、旧格式存储、全新挂载——没有检查点，不还原任何文件。

### 仅权限变化

只改变权限时，行里记录的 `mode` 会刷新，但不会产生新版本，也不会触发还原。`mode` 只在内容被还原时顺带重新应用。

## 六、其它限制

| 限制 | 影响 |
| --- | --- |
| 保留窗口之外 | 每个会话只保留最新 100 张检查点；更早的目标没有检查点，不还原文件 |
| 旧历史 | 这个存储存在之前的消息没有检查点 |
| 子代理 | 子代理运行在自己的会话里；父会话不追踪它的编辑，子会话内也不提供回退 |
| fork / 新 session id | 新的 session id 得到空存储，不继承文件历史 |
| 符号链接与硬链接 | 首次看到时就不捕获；已跟踪路径后来变成符号链接、硬链接或其它非普通文件时，还原会跳过并报告 |
| 父目录被重指 | 父目录解析到的位置与捕获时不同时，跳过并报告 |
| 还原中途崩溃 | 每个文件是原子替换，但整轮不是跨文件事务；崩溃可能留下「部分已还原、部分未还原」。对同一目标再回退一次即可收敛 |
| 断电 | 不做 fsync；最后一次检查点写入可能丢失，下一次消息边界会重建 |

## 七、边界为什么画在这里

边界来自模型本身：检查点覆盖 Agent 通过 `write`/`edit` 做的编辑，以及这些已跟踪文件的外部改动，之外属于工作区历史。工作区历史已经有归属——Git，或项目自选的快照工具；在这里再造一份，等于复制一个已经有人维护的权威。先例、分工，以及全树存储在这里的真实代价，见[设计边界](../boundaries.zh.md)。

插件只写回它记录过的状态，并逐项报告每个未触碰的路径；它不猜测未记录的内容。

需要工作区级别的精确历史时，请使用 Git。
